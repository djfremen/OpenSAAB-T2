# K2401 orientation check — 2026-09-23

Installed app: `com.opensaab.tech2.headunit32`, version
`0.1.0-headunit.20` / 100020. No APK/source changes were needed.

The owner's photo showed the whole Android surface sideways, including its
navigation/status bars. ADB confirmed 720×1280 / rotation 0. The running app had
unspecified orientation (the head-unit builder removes phone portrait locks).
Returning to the vendor Home activity did not fix it: Home requested landscape,
but the display remained portrait. Auto-rotation was enabled with no rotation
sensor present. Thus an app portrait lock was not the cause on this installed APK.

After confirming the diagnostic session had ended and USB was released, applied:

```sh
adb -s <device> shell wm set-user-rotation lock 1
```

The display immediately changed to 1280×720 / ROTATION_90. Android settings now
report `accelerometer_rotation=0`, `user_rotation=1`. This is a per-device
landscape lock; it does not force a portrait-mounted head unit into landscape.
The original values were auto-rotation enabled and user rotation 0.
To restore that prior configuration: `wm set-user-rotation free 0`.

Verified by returning to the same app task and inspecting both the Chipsoft
screen and MainActivity: horizontal layout, visible controls, full-width fixed
Donate footer, and INIT_AUTH/cleared visible in the workspace. Saved DTC reports
still include the completed read from 04:16:25Z. Rotation recreated the diagnostic
screen, so its transient output cleared; the saved report was retained. No new
vehicle operation, DTC clearing, security processing or firmware change occurred.

- `evidence/k2401-orientation-2026-09-23/landscape-workspace.png`

Reboot persistence has not been tested. Include sensorless head-unit rotation
settings in future setup/visual checks before attributing sideways rendering to
an APK. Public downloads remain unchanged.
