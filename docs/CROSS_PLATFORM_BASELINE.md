# Cross-platform Consistent Baseline

The user-approved product workflow is maintained in the companion
`djfremen/OpenSAAB` repository at `releases/consistent-baseline/README.md`.
Local checkpoint: `0d2afc5b7d7235bfc5b2e3f682eaab856f5f20a5` on
`windows-native-emulator`. This reference does not imply GitHub publication.

The authoritative contract, five-target capability inventory and exact-artifact
qualification gate live there. Android ARM64 and ARM32 are separate targets;
build success or an older head-unit bench result cannot qualify the current APK.
The source audit found 59 identical Rust files, 10 changed files and this tree's
additional `adapters/chipsoft/dtc.rs`. Shared source reconciliation is pending;
no Android code is replaced by the older desktop copy.

Preserve this branch's catalog and language installation gains, immutable
original images, working-card backup, cancellation/recovery, fast ARM32 startup,
deferred CANdi and adapter-specific command boundaries. The local build source
is `afea880`; Pixel/Android Studio evidence is documented at `d0e9afc`.

Follow the common workflow: install compatible ABI → language choice → verified
firmware preparation → offline or adapter connection → fresh VIN plus complete
Trionic 8 HS-CAN DTC report → diagnostic menus. App-control localization is still
pending and must not be confused with diagnostic firmware language support.

Before qualification, record clean install and upgrade preservation, menu and
language behavior, physical Chipsoft startup, unplug/cancel/reconnect/restart,
and artifact-specific receipts. The new ARM32 build needs a physical retest;
the integrated ARM64 VIN/DTC startup needs a live adapter test. Keep the German
0.000 splash discrepancy open until investigated.

Do not maintain a second completion matrix here. Update the companion inventory
and regenerate the personal-dashboard card from that inventory. Raw device logs,
VINs, firmware images and signing material remain private.
