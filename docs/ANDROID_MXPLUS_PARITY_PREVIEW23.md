# Android native-control parity · 0.1.1-preview.23

The owner’s preview.21 MX+ session was a bounded clearing session. The original firmware’s HS-CAN security-seed request `02 27 01 00 00 00 00 00` was rejected locally before transmission; it was not an ECU denial. Service resets were outside that authority.

Preview.23 retains Read + write a real explicit MX+ authority, bound to the authenticated native role. Read-only remains the default. Full control passes unchanged original guest frames on validated HS/SW routes, including service and security requests, as the existing full-control USB paths do. It preserves framing, electrical checks, ownership, cancellation, confirmations and actual ECU security. It does not make unsupported buses available or claim every programming operation works.

Get security access now offers Bluetooth and selects the separate seed-collection profile. The common SecurityAccessView owns collection, explicit disclosure consent, service authentication, response validation, stable-card checks and import. Each native session records the freshly identified vehicle and card baseline. A completed processing handoff requires confirmed protocol/Bluetooth cleanup; resuming offers the common mode choice and freshly checks the same VIN. No operator password is introduced. Collection cards and historical evidence are preserved.

The previous chooser incorrectly hid Nano’s existing release full-native authority; it now offers Read + write explicitly. The shared legacy/USB worker and MX+ worker use the same newly built native bytes; five other components retain their exact pins. The card-derived localized transfer parser is byte-identical to the Apple silicon/iOS source from efad90e5bb06c54fb99770396f71a13c47066e6d. Android now consumes its native completion witness together with the matching validated working SSA, rather than relying only on English screen text. Original guest flash writes are still required. Exact installed and physical checks are recorded separately; no inherited platform, adapter, language or whole-vehicle pass.

The read-only, bounded clearing, counter-reset and security-only profiles keep their limits. New full-control selection opens no transport until Connect, performs no write on its own and replays no operation. Unavailable actions remain gaps. Preview.21 and earlier signed artifacts are immutable. This candidate is not published. Full native sessions have no offline thirty-minute/instruction or private thirty-minute cutoff: a long original service operation must not be terminated by those preview budgets. Full control still supports explicit operator cancellation and verified cleanup; its host stop grace is fifteen seconds. Preview.22 never started a native vehicle session during its two Bluetooth failures and is preserved as a superseded test artifact.

The emulation evidence schema accepts the explicit full/seeds profiles, retains the legacy native-read profile name and records the actual unbounded full-control deadline. This prevents profile-validation from stopping native startup.
